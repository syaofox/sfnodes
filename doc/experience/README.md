## 维护规则

- **取号**：新增经验 = 当前最大 §N + 1（见本文件顶部数字），追加到对应主题文件末尾并在上表加行；编号只增、不复用、不重排；改号/重排须全文替换引用（`tests/check_docs.py` 校验唯一性与引用可解析）。
- **新建主题文件**：确属新类别且现有主题均不适配时才新建（英文短名对齐节点族/领域），标题只写主题，并更新本表（最大 §N 不变）。
- 最小事实订正：失效的文件/函数/包/API 名、断链引用、明显错别字可就地修正；**不得改写历史结论与论证**；拿不准的过时内容用带日期的补注而非改原文。
- 取代机制：机制被后续方案取代时，新经验仍开新 §N，并在旧节开头加一行 `> ⚠️ 已被 §N 取代（YYYY-MM）`（新节注明取代关系，双向指针）。
- **引用规范**：跨文件引用一律写「文件名 §N」（如 `nodes-image.md §118`），同文件内可简写 `§N`；小节号必须写全、带上完整章节号，不得省略上级（如三位小节号须写 `§118.3.7` 形式）。
- 章节内小节号（如 §19.7）指「§19 文件内的 `### 7.`」，随所属章节走。
- **索引维护**：上表条目 = `§N 标题`，标题逐字取自对应 `## N.` 标题行（允许截短为其前缀）；细节不重复收录，避免索引与正文双份漂移。
- `AGENTS.md` 只引用本表，不增补索引行。
